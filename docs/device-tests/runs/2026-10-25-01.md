## Findings

1. **Fixed: the Mac app crashed under XCUITest on the pairing screen.**
   - The address on the ready card was selectable and had its own accessibility label, and SwiftUI's label lookup
     overflowed the stack.
   - The label is now on a container and the address is not selectable (`a630f77`).
   - A label on the Text itself also made iOS report it as clipped.
2. **Fixed: accessibility issues the audits found on the devices:**
   - 17 pt text links (now 44 pt);
   - the banner's action without its own identifier;
   - no role on the countdown and the numbered steps (Mac);
   - a Dynamic Type issue in the countdown (iOS).

   (`a630f77`)
3. **Open: Mac app → CLI over Bonjour on this Mac failed 2 of 3 runs.**
   - The app found the CLI but no code prompt came in 25 s.
   - The same test passes on the iPhone.
   - This Mac's Bonjour resolves a receiver's host to its Wi-Fi address and to three virtual-machine bridge addresses,
     two of which refuse connections.
   - The cause is not established. Any fix is in the discovery rules and needs its own plan.
4. **The first iPhone ↔ Mac device-to-device run failed once.** The iPhone, just installed, did not start receiving
   within 60 s. The next runs passed.
5. **Environment notes:**
   - Moving the repository to another drive left a stale CLI path compiled into the e2e test binary
     (`cargo clean -p dropumi-cli` fixed it).
   - It also reset UI-automation approval for the Mac test runner.
