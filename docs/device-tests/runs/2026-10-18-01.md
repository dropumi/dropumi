## Findings

1. **Fixed: the app showed nothing when the core refused a device it could not name.** In the second iPhone run,
   `apple_ios_device_bonjour_cli_finds_app_at_random_host` waited for "the refused sender" and the app had no notice
   (`"banner":""`). With Paired only, the core refuses a device it does not know during the handshake and reports the
   closed session with no peer; the app showed a notice only for a named peer. Fixed in `97b8293` ("A device was
   refused"), with four `AppModelTests`; the next two runs passed.
2. **Fixed: on the Mac, VoiceOver could not open the "…" menus.** The audit reported "Action is missing" on Nearby's
   More button. A SwiftUI `Menu` with a custom label offered only `AXPress`, not `AXShowMenu` (Safari's menu buttons
   offer both); the Paired devices row menu had the same defect. Fixed in `45e6baa`: of seven menu styles tried,
   only the button menu style with a plain button style offers both. Regression tests: the audits in
   `testNearbyNeverLabelsADevicePaired` and the new `testPairedDevicesListsTheDeviceWithItsActions`, which failed
   with "Action is missing" without the fix.
3. **Not the app's: three Mac audit results.** Each is exempted in the test with its evidence (`964982e`,
   `0a2b82d`); the consent and code screens are unchanged:
   - "Contrast failed" on the empty-Nearby text that a sheet covers: the audit measured the sheet's pixels over it;
     the same text passes with no sheet.
   - "Element has no description" on a group with exactly the sheet's frame: a probe app showed that every SwiftUI
     sheet on macOS 27.0.1 has this root group, and that a label on the sheet's content lands on an inner element.
   - "Contrast failed" on the code digits, which measure 13.00:1 on screen (#F5F8FB on #192E46, from a capture of the
     element's frame only); the iPhone's audit passes the same view.
4. **First-use permissions.** The first iPhone run failed `apple_ios_device_app_sends_to_cli_after_code` (waiting for
   "a prompt") while iOS asked for Local Network access; the first Mac Bonjour run failed both Bonjour tests until
   Local Network was allowed. Answer both questions before a run.
5. **Mac UI tests open the window themselves.** Under XCUITest the Mac app did not always show its main window at
   launch, so UI-test launches open it (`f642ef7`). Whether a normal launch shows it belongs to UI-4 (Not tested).
6. **Privacy of Mac UI test results.** XCUITest records the main display into the `.xcresult` bundle, even while the
   app's windows are on the built-in display. The bundles from this session were deleted unopened; never share one.
7. **The iPhone must be unlocked.** One iPhone run stopped before its first test with "Timed out while enabling
   automation mode" while the phone was locked; the run with the phone unlocked passed.
